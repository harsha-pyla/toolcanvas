How Does the Identifier Tokenizer Work?

Converting programming identifiers is far more nuanced than simple string replacement. Different coding styles separate words using uppercase transitions, underscores, hyphens, dots, or spaces. ToolCanvas utilizes a specialized regex word-boundary tokenizer:

CamelCase Transition Detection: Detects boundary points between lowercase characters and subsequent capital letters (e.g. fooBar splits into foo and Bar).

Acronym Boundary Handling: Correctly isolates acronym sequences followed by a capitalized word (e.g. XMLHTTPRequest splits into XML, HTTP, and Request instead of corrupting the acronym).

Universal Delimiter Parsing: Strips hyphens, underscores, dots, and whitespace, isolating the underlying semantic words before reassembling them into your chosen target convention.

Line-by-Line Independence: By treating each line as a distinct identifier, you can convert lists of 500 database attributes in one click without them collapsing into a single run-on token.

Programming Language Naming Standards

Standard casing conventions by programming language and software framework:

JavaScript & TypeScript
  • camelCase: Variable names, object properties, and function definitions (e.g. getUserProfile, totalAmount).
  • PascalCase: Classes, interfaces, type aliases, and React components (e.g. UserProfileCard, PaymentResponse).
  • kebab-case: npm package names and CSS class selectors.
Python & Data Science
  • snake_case: Function names, methods, variables, and module filenames per PEP 8 (e.g. calculate_tax, order_id).
  • PascalCase: Class names and exception types (e.g. DatabaseConnection).
C# & .NET
  • PascalCase: Methods, public properties, classes, namespaces, and enums (e.g. CalculateTotal, CustomerAddress).
  • camelCase: Private fields (often with underscore prefix) and method parameters.
Web Standards & DevOps
  • kebab-case: CSS classes, HTML data attributes (data-user-id), REST API endpoints (/api/v1/user-settings), and Kubernetes resource names.
  • snake_case: SQL column names and PostgreSQL database tables.

The 4 Code Casing Styles Explained

  • camelCase: The first word begins with a lowercase letter, and every subsequent word starts with an uppercase letter. No spaces, hyphens, or underscores are used (e.g. userId, paymentMethodType).
  • PascalCase: Every word begins with an uppercase letter, including the very first word. No delimiters are used (e.g. UserId, PaymentMethodType). Also known as UpperCamelCase.
  • kebab-case: All words are written in lowercase and joined by single hyphens (e.g. user-id, payment-method-type). Also known as dash-case or spinal-case.
  • snake_case: All words are written in lowercase and joined by single underscores (e.g. user_id, payment_method_type). Also known as underscore_case.

Best Practices for Code Identifiers

  • Batch SQL Columns: When creating TypeScript types from SQL schemas, paste the column list directly into the editor and click camelCase for instant property names.
  • Avoid Double Delimiters: The tokenizer strips redundant underscores or hyphens (such as user__profile or order--id), producing clean single-delimiter outputs.
  • Numbers in Variable Names: Numbers attached to words (e.g. utf8Encoding or sha256Hash) are preserved without unwanted separation.

What is the difference between camelCase and PascalCase?

In camelCase, the first letter of the first word is lowercase (e.g. userId). In PascalCase (also known as UpperCamelCase), the first letter of the first word is capitalized (e.g. UserId).

Why does CSS use kebab-case instead of camelCase?

CSS is historically case-insensitive in HTML and uses hyphens (e.g. font-size, border-radius) to improve human readability. In JavaScript, CSS properties are accessed via camelCase (e.g. style.fontSize) because hyphens are interpreted as subtraction operators.
